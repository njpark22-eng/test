# 기능 명세: 가상 계측 데이터 저장과 결과 이력

**기능 브랜치**: `002-persistence` (작업 브랜치는 `main`, 브랜치는 만들지 않음)
**작성일**: 2026-11-13
**상태**: 초안
**입력**: 가상 계측 엑셀을 웹에서 올려 분석하고, 원본·분석 결과·판정에 쓴 기준값(고정값)을 저장해 나중에 목록과 상세로 다시 본다. 데이터는 가상 신호뿐이고 로그인은 없다. 이 기능은 `001-web-demo`(읽기 전용 화면) 위에 쓰기 기능을 더한다. 원칙은 `.specify/memory/constitution.md`, 규칙은 `CLAUDE.md`를 따른다.

## 사용자 시나리오와 테스트 *(필수)*

### 사용자 스토리 1 - 가상 계측 엑셀 올리고 분석하기 (우선순위: P1)

사용자가 웹 화면에서 채널별 가상 계측 엑셀을 올리고, 채널마다 rpm과 볼 개수를 확인한 뒤 분석을 실행해 판정 결과를 본다. 올린 원본과 분석 결과는 저장된다.

**우선순위 이유**: 이 기능의 핵심이다. 올리기, 입력 검증, 분석, 저장이 한 흐름이어야 이후 목록·상세·기준값이 의미를 가진다.

**독립 테스트**: 가상 엑셀 1~5개를 올려 분석을 실행하고, 판정이 같은 파일을 로컬 `--offline`으로 돌린 결과와 같은지, 저장된 원본의 해시가 올린 파일의 해시와 같은지 확인한다.

**인수 시나리오**:

1. **조건** 쓰기 토큰을 입력했고 형식에 맞는 가상 엑셀을 골랐다, **동작** 파일을 올린다, **결과** 채널별 데이터 표 앞부분과 회전수(자동 추정값)가 보이고, 볼 개수 기본값은 1이다.
2. **조건** 올린 신호의 1X 성분이 최대 피크의 20% 미만이 되는 rpm을 입력했다, **동작** 분석을 요청한다, **결과** 경고를 보여 주고 rpm을 다시 입력받는다.
3. **조건** 볼 개수에 1~100 밖의 값이나 정수가 아닌 값을 입력했다, **동작** 분석을 요청한다, **결과** 오류 문구를 보여 주고 실행하지 않는다.
4. **조건** 모든 입력이 유효하다, **동작** 분석을 실행한다, **결과** 채널별 판정 표와 FFT 그래프가 보이고 원본과 분석 결과가 저장된다.
5. **조건** 업로드 화면을 연다, **동작** 화면을 본다, **결과** '가상 데이터만 올리세요. 실제 계측 데이터는 금지'가 항상 보인다.

---

### 사용자 스토리 2 - 저장된 결과 목록과 상세 보기 (우선순위: P2)

누구나(로그인 없이) 저장된 분석 실행의 목록을 보고, 하나를 열어 채널별 판정, 근거 수치, FFT 그래프, 판정에 쓴 기준값을 다시 본다.

**우선순위 이유**: 저장의 가치는 다시 볼 수 있다는 데 있다. 읽기는 공개이므로 시연 참석자도 결과를 볼 수 있다.

**독립 테스트**: 분석을 두 번 실행한 뒤 목록에 두 건이 최신순으로 보이고, 상세에서 저장 당시와 같은 수치와 판정이 나오는지 확인한다.

**인수 시나리오**:

1. **조건** 저장된 실행이 있다, **동작** 목록 화면을 연다, **결과** 실행 시각, 채널 수, 판정 요약이 최신순으로 보인다.
2. **조건** 목록에서 한 건을 골랐다, **동작** 상세를 연다, **결과** 채널별 rpm, 볼 개수, 최대 피크 RMS, 2X/1X, BPFO/1X, 판정, FFT 그래프, 판정에 쓴 기준값(RMS 4.5, 2X/1X 0.5, 베어링/1X 0.7, 저주파 20)이 보인다.
3. **조건** 저장된 실행이 없다, **동작** 목록을 연다, **결과** 비어 있다는 안내와 올리는 방법이 보인다.
4. **조건** 나중에 코드의 기준값이 바뀌었다, **동작** 예전 실행의 상세를 연다, **결과** 저장 당시 기준값을 그대로 보여 준다(과거 결과는 다시 계산하지 않는다).

---

### 예외 상황

- 쓰기 토큰이 없거나 틀리면 업로드와 분석 저장이 모두 거부된다. 읽기(목록, 상세)는 토큰 없이 된다.
- 올린 파일이 `.xlsx`가 아니거나, 시트에 데이터 행이 없거나, 샘플링 주파수가 5,120 Hz(허용오차 0.1%)와 다르면 어떤 문제인지 한 줄로 알리고 저장하지 않는다.
- 파일 크기가 한도를 넘거나 짧은 시간에 올린 횟수가 한도를 넘으면 거부하고 한도와 기다릴 시간을 알린다.
- 같은 파일(같은 해시)을 다시 올리면 원본은 중복 저장하지 않고 기존 원본을 참조하며, 분석 결과는 새 기록으로 남긴다.
- 저장소(데이터베이스)에 연결할 수 없으면 분석 결과 화면은 보여 주되 저장 실패를 분명히 알리고, 읽기 화면은 연결 오류를 한 줄로 안내한다.
- 채널은 1~5개까지다. 6개 이상이면 거부한다(현재 시연 범위).
- 저장된 원본과 분석 결과는 수정하거나 삭제할 수 없다. 화면과 요청 어디에도 수정·삭제 기능이 없다.

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 시스템은 사용자가 올린 가상 계측 엑셀(1개 = 채널 1개, A열 `time_s`, B열 `velocity_mm_s`, 5,120 Hz)을 읽어 분석해야 한다. 파일은 읽기만 하고 변형하지 않는다.
- **FR-002**: 시스템은 올린 원본 파일의 바이트, SHA-256 해시, 채널, 업로드 시각을 추가만 가능한 형태로 저장해야 한다. 저장된 원본은 수정·삭제할 수 없다.
- **FR-003**: 시스템은 분석 실행 1건에 채널 1~5개 파일을 묶어 다뤄야 하며, 채널마다 rpm(0 초과 20,000 이하)과 볼 개수(1~100의 정수)를 입력받아야 한다. 볼 개수 기본값은 1이다.
- **FR-004**: 시스템은 파일을 올릴 때 신호의 FFT 최대 피크(3 Hz 이상)를 1X로 보고 rpm을 자동으로 채워야 한다. 사용자가 바꾼 rpm의 1X 성분이 최대 피크의 20% 미만이면 경고하고 다시 입력받아야 한다. 이 동작은 로컬 UI(`vibe_agent`의 `detect_rpm`, `rpm_mismatch`)와 같아야 한다.
- **FR-005**: 시스템은 판정과 FFT 계산에 `vibe_agent`의 `spectrum`, `analyze_signal`, `rule_verdict`, `RULES`, `read_xlsx`를 import해서 써야 하며 같은 로직을 다시 구현해서는 안 된다.
- **FR-006**: 시스템은 분석 결과(`analyze_signal` 값 전부, `rule_verdict` 판정, 판정에 쓴 기준값, 사용한 rpm·볼 개수)를 추가만 가능한 형태로 저장해야 한다. 결과는 수정·삭제할 수 없고, 과거 결과를 다시 계산하지 않는다.
- **FR-007**: 시스템은 저장된 실행의 목록(최신순)과 상세(채널별 판정, 근거 수치, FFT 그래프, 기준값 버전)를 공개로 보여 줘야 한다.
- **FR-008**: 판정 기준값(RMS 4.5, 2X/1X 0.5, 베어링/1X 0.7, 저주파 20)은 코드의 값으로 고정한다. 웹에서 기준값을 바꾸거나 새 버전을 추가하는 기능은 없다. 시스템은 판정에 쓴 기준값을 `vibe_agent`의 현재 값에서 읽어 분석 결과와 함께 기록하고(FR-006), 기준값이 바뀐 뒤에도 과거 기록은 저장 당시 값을 보여 준다. 기준값 변경은 기존 규칙(`rule_verdict`와 `RULES` 동시 수정, tests/ 동시 수정)을 따른다.
- **FR-009**: 쓰기(파일 올리기, 분석 결과 저장)는 공유 토큰이 있어야만 허용해야 한다. 읽기는 토큰 없이 허용한다. 토큰 값은 코드·저장소·로그·응답에 남기지 않는다.
- **FR-010**: 시스템은 업로드 파일 크기, 시간당 업로드 횟수, 파일 형식을 검증하고 한도를 넘으면 원인과 조치를 한 줄로 알리며 거부해야 한다.
- **FR-011**: 업로드 화면에는 '가상 데이터만 올리세요. 실제 계측 데이터는 금지'를 항상 표시해야 한다.
- **FR-012**: 검수 승인(`approve.py`)과 `review-N.json` 생성은 웹에 제공하지 않는다. tkinter `--ui`는 로컬 전용으로 유지하며 이 기능이 바꾸지 않는다.
- **FR-013**: 화면 문구는 SPEC의 판정명 표기를 그대로 쓰고, 화면은 CLAUDE.md의 색조와 슬롭 방지 규칙(파랑 `#0C4CA3`·회색, 판정 의미색 3가지, 판정명 글자와 기호)을 따라야 한다. 이 명세와 이후 `specs/002-persistence/` 문서는 모두 한글로 쓴다.
- **FR-014**: 저장소에 연결할 수 없을 때 시스템은 저장 실패 또는 조회 실패를 사용자에게 알려야 하며, 실패한 요청이 부분 저장을 남기지 않아야 한다(원본과 결과는 함께 저장되거나 모두 저장되지 않는다).

### 주요 개체

- **계측 원본(Measurement File)**: 올린 엑셀 한 개. 바이트, SHA-256 해시, 채널, 업로드 시각. 수정·삭제 불가.
- **분석 실행(Analysis Run)**: 한 번의 분석. 실행 시각, 판정에 쓴 기준값(RMS 한계, 2X/1X, 베어링/1X, 저주파), 포함된 채널 결과 1~5개. 수정·삭제 불가.
- **채널 결과(Channel Result)**: 채널 하나의 rpm, 볼 개수, `analyze_signal` 값, 판정, 연결된 계측 원본. 수정·삭제 불가.

## 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 사용자가 가상 엑셀 5개를 올려 분석 결과를 볼 때까지 3분 이내에 마칠 수 있다.
- **SC-002**: 기본 가상 데이터 5개를 올려 분석하면 판정이 5/5로 기대값(CH1 재계측 권장 / CH2 정상 / CH3 베어링 점검 요망 / CH4 발란싱 요망 / CH5 정렬 요망)과 일치하고, 같은 파일을 로컬 `--offline`으로 돌린 판정과 100% 같다.
- **SC-003**: 저장된 원본의 해시가 올린 파일의 해시와 100% 일치하고, 저장 후 어떤 화면·요청으로도 원본과 결과를 수정하거나 삭제할 수 없다.
- **SC-004**: 토큰이 없거나 틀린 쓰기 요청은 100% 거부되고, 읽기 화면은 토큰 없이 열린다.
- **SC-005**: 잘못된 파일(형식, 샘플링 주파수, 크기)과 잘못된 입력(rpm, 볼 개수)은 100% 저장 전에 거부되고, 사용자는 원인을 한 줄로 읽는다.
- **SC-006**: 저장된 결과 목록과 상세는 1초 안에 사용자가 읽을 수 있는 상태로 보인다(가상 데이터 100건 기준).
- **SC-007**: 화면 문구와 디자인이 CLAUDE.md 슬롭 방지 체크리스트 위반 0건이다.

## 가정

- 데이터는 가상 신호뿐이고 개인정보가 없다. 로그인은 두지 않고, 쓰기는 공유 토큰 하나로 제한한다. 읽기는 공개다. 이 가정이 깨지면(실제 데이터) 별도 명세로 인증과 접근 제어를 다시 정한다.
- 저장소는 사용자가 정한 Neon Postgres다(Vercel 연동). 연결 정보는 환경변수로만 두고 저장소에 올리지 않는다. 구체 구조는 `/speckit-plan`에서 정한다.
- 한도 기본값: 파일 1개 1 MB 이하(가상 데이터 엑셀은 약 170 KB), 한 번에 올리는 합계 4 MB 이하(배포 환경의 요청 크기 제한 약 4.5 MB 이내), 분석 저장은 시간당 30회. 값은 계획 단계에서 플랜별 제한을 확인해 조정한다.
- 채널 수는 시연 범위인 1~5개이고 샘플링 주파수는 5,120 Hz로 고정이다.
- 분석 실행 1건은 채널 파일을 한 번에 묶어 올린 것을 뜻한다. 같은 채널 파일을 나중에 추가로 붙이는 기능은 범위 밖이다.
- 결과 파일(`result-N.xlsx/png`) 내려받기, 검수 승인, 에이전트(Claude API) 판정, 실제 계측 데이터, 웹에서 기준값을 바꾸는 기능(기준값 버전 관리)은 범위 밖이다. 기준값을 고정하기로 했다(2026-11-13 사용자 결정).
- `001-web-demo`의 화면(`/`, `/api/analyze`)은 그대로 유지하고, 이 기능은 그 위에 올리기·이력·기준값 화면을 더한다.
