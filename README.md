# vibe-agent: 진동 진단 에이전트 (시연용)

회전 설비(모터, 펌프 등)의 **진동 계측 데이터(엑셀)** 를 FFT로 분석해 설비 상태를 다섯 가지로 판정하는 프로그램입니다.

| 판정 | 뜻 |
|---|---|
| 정상 | 진동이 기준 이하이고 이상 징후 없음 |
| 베어링 점검 요망 | 진동은 기준 이하지만 베어링 결함 성분이 큼 |
| 발란싱 요망 | 진동이 기준 초과, 회전 주파수(1X) 성분이 지배적 (회전체 불균형) |
| 정렬(Misalignment) 요망 | 진동이 기준 초과, 2X 성분이 큼 (축 정렬 불량) |
| 재계측 권장 | 저주파 노이즈가 너무 커서 분석이 불가능, 다시 측정해야 함 |

두 가지 방식으로 판정할 수 있습니다.
- **규칙 기반 (`--offline`)**: 정해진 규칙만으로 판정합니다. 인터넷도 API 키도 필요 없습니다. **처음 실행해 본다면 이 방식으로 시작하세요.**
- **Claude 에이전트 (기본)**: Claude가 도구(`list_signals`, `analyze_signal`)를 직접 호출하며 분석하고 설명까지 붙입니다. Anthropic API 키가 필요합니다.

> 시연용 데이터는 모두 numpy로 만든 **가상 신호**입니다. 실제 설비 데이터와 개인정보는 들어 있지 않습니다.

## 1. 준비물

| 준비물 | 설명 | 확인 방법 |
|---|---|---|
| Python 3.10 이상 | 프로그램 실행 환경 | `python --version` |
| uv | Python 패키지 설치/실행 도구 (권장) | `uv --version` |
| git | 저장소를 내려받을 때 사용 | `git --version` |
| (선택) Anthropic API 키 | Claude 에이전트 모드에서만 필요 | 아래 4장 참고 |

uv가 없다면 먼저 설치합니다.
- Windows (PowerShell): `powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"`
- macOS / Linux: `curl -LsSf https://astral.sh/uv/install.sh | sh`
- 설치 후 **터미널을 닫았다가 다시 열고** `uv --version`으로 확인합니다.

uv를 쓰고 싶지 않다면 `pip install numpy anthropic matplotlib openpyxl pytest`로 설치한 뒤, 아래 명령의 `uv run python`을 `python`으로 바꿔 실행해도 됩니다.

## 2. 설치

저장소를 내려받은 폴더(`vibe-agent`, `vibe_agent.py`가 있는 곳)에서 터미널을 엽니다.

```
git clone <저장소 주소>
cd vibe-agent
uv sync
```

`uv sync`가 필요한 라이브러리(numpy, anthropic, matplotlib, openpyxl, pytest)를 자동으로 설치합니다. 처음 한 번만 하면 됩니다.

## 3. 5분 빠른 시작 (API 키 없이)

1. 규칙 기반으로 실행합니다. 시연용 데이터(`data/CH1~CH5.xlsx`)는 저장소에 이미 들어 있으므로 따로 만들 필요가 없습니다.

   ```
   uv run python vibe_agent.py --offline
   ```

2. 터미널에 판정 규칙과 채널별 판정이 출력됩니다. 정상이라면 아래와 같이 나옵니다.

   | 채널 | 회전수 | 판정 | 가상 신호의 특징 |
   |---|---|---|---|
   | CH1 | 900 rpm | 재계측 권장 | 저주파 노이즈가 큼 |
   | CH2 | 1800 rpm | 정상 | 정상 신호 |
   | CH3 | 1500 rpm | 베어링 점검 요망 | 베어링 성분이 있음 (볼 9개) |
   | CH4 | 1200 rpm | 발란싱 요망 | 1X가 크고 기준 초과 |
   | CH5 | 2400 rpm | 정렬 요망 | 1X와 2X가 모두 크고 기준 초과 |

   각 줄에는 `peak_rms_mm_s`(최대 피크 진동), `rms_1X`, `rms_2X` 같은 근거 수치도 함께 나옵니다.

3. 실행이 끝나면 **프로그램을 실행한 폴더**에 결과 파일 2개가 생깁니다. (자세한 설명은 6장)
   - `result-1.xlsx`: 채널별 결과 표 (엑셀로 열기)
   - `result-1.png`: 채널별 FFT 그래프와 판정 설명 (이미지로 열기)

4. 결과를 확인합니다.
   - Windows: `start result-1.png`, `start result-1.xlsx`
   - macOS: `open result-1.png`
   - Linux: `xdg-open result-1.png`
   - 또는 탐색기/Finder에서 폴더를 열어 더블클릭합니다.

여기까지 되었다면 프로그램은 정상 동작하는 것입니다. 나머지는 선택 사항입니다.

## 4. 실행 모드

모든 명령은 저장소 폴더에서 실행합니다.

| 명령 | 하는 일 | API 키 |
|---|---|---|
| `uv run python vibe_agent.py --offline` | 규칙 기반 판정, 결과 파일 저장 | 불필요 |
| `uv run python vibe_agent.py` | Claude 에이전트가 도구를 호출하며 판정. 키가 없으면 자동으로 규칙 기반으로 실행 | 필요 |
| `uv run python vibe_agent.py --plot` | 위 실행에 더해 채널별 FFT 스펙트럼 `spectra.png` 추가 생성 | 불필요 |
| `uv run python vibe_agent.py --ui` | 파일을 직접 고르는 창(UI) 실행. 키가 없거나 `--offline`을 같이 주면 규칙 기반 | 선택 |
| `uv run python vibe_agent.py --make-data` | 가상 계측 데이터를 `data/CH1~CH5.xlsx`로 **다시 생성** (덮어씀) | 불필요 |

옵션은 함께 쓸 수 있습니다. 예: `--offline --plot`, `--ui --offline`.

### Claude 에이전트 모드 (API 키 필요)

Anthropic API 키를 환경변수로 설정한 뒤 `--offline` 없이 실행합니다. 키는 **현재 터미널 창에서만** 유효하며, 창을 닫으면 사라집니다.

- Windows PowerShell: `$env:ANTHROPIC_API_KEY = "여기에_키"`
- Windows 명령 프롬프트(cmd): `set ANTHROPIC_API_KEY=여기에_키`
- macOS / Linux: `export ANTHROPIC_API_KEY=여기에_키`

그다음 `uv run python vibe_agent.py`를 실행하면 `[도구 호출]` 로그가 나오고, 채널별 판정과 Claude의 설명이 출력됩니다. 쓰는 모델을 바꾸려면 환경변수 `CLAUDE_MODEL`을 설정합니다 (기본값 `claude-sonnet-5-5`).

주의할 점:
- 키는 **파일에 적지 말고** 환경변수로만 사용하세요. `.env` 파일에 두거나 저장소에 커밋하지 않습니다.
- 화면 공유나 발표 중에는 키가 화면에 보이지 않게 주의하세요.
- API 호출에는 비용이 들 수 있습니다. 오류가 나면 `--offline`으로 바꿔 실행하세요.

### 스펙트럼 그림 `--plot`

```
uv run python vibe_agent.py --offline --plot
```

`spectra.png`가 생성됩니다. 채널별 FFT 그래프에 1X, 2X, 베어링 주파수(BPFO)와 허용 기준선(4.5 mm/s)이 표시됩니다. (`result-N.png`와는 별개의 파일입니다.)

### 파일 선택 UI `--ui`

```
uv run python vibe_agent.py --ui --offline
```

창이 열리면 다음 순서로 진행합니다.

1. **채널 개수 입력**: 안내 문구는 1~32이지만 현재는 5채널까지만 가능합니다. 5를 넘기면 경고 후 다시 입력받습니다.
2. **채널마다 `파일 선택`**: `data/CH1.xlsx` ~ `data/CH5.xlsx`를 순서대로 고르면 데이터 표(앞 1,000행)와 시간 신호 그래프가 보입니다.
3. **회전수(rpm)**: 파일을 고르면 신호의 1X에 맞춰 **자동으로 채워집니다.** 다른 값을 직접 입력하면 신호의 1X와 맞는지 바로 확인하고, 맞지 않으면 경고 후 다시 입력받습니다.
4. **베어링 볼 개수**: 1~100의 정수입니다. 기본값은 CH3만 9, 나머지는 1입니다. 기본값과 다르게 입력하면 확인창이 뜹니다. `1`은 "베어링을 쓰지 않는 장비"라는 뜻이라 베어링 판정을 하지 않습니다.
5. **`분석 실행`**: 결과 탭에 채널별 FFT 그림, RMS 기준 만족/불만족/재계측 표, 결함 진단 설명이 표시됩니다. 결과 파일(`result-N.xlsx`, `result-N.png`)도 함께 저장됩니다.

`tkinter`가 없으면 UI를 쓸 수 없습니다. Windows/macOS의 일반 Python에는 포함되어 있고, Linux에서는 `sudo apt install python3-tk`로 설치합니다.

## 5. 데이터 형식

- 엑셀 파일 1개 = 채널 1개입니다. (`data/CH1.xlsx` = CH1)
- **A열 `time_s`**(시간, 초), **B열 `velocity_mm_s`**(진동 속도, mm/s)만 분석에 사용합니다. 시트에 들어 있는 그래프는 무시합니다.
- 샘플링 주파수는 **5120 Hz**여야 합니다. 다르면 오류가 납니다. 시연 데이터 길이는 2초입니다.

**입력 데이터 엑셀 파일은 수정하지 마세요.** 계측기에서 받은 원본 데이터로 간주합니다. 프로그램도 파일을 읽기 전용으로만 열며 덮어쓰지 않습니다. 결과는 `result-N.xlsx`, `result-N.png`로 따로 저장됩니다. (예외: `--make-data`는 가상 데이터 `data/CH1~CH5.xlsx`를 새로 만드는 명령이며, 실제 계측 데이터에는 쓰지 마세요.)

## 6. 결과 파일 보는 법

분석을 실행하면(`--offline`, 에이전트, `--ui` 모두) **실행한 폴더**에 두 파일이 같은 일련번호로 저장됩니다.

- **`result-N.xlsx`**: 채널별 결과 표입니다. 열 순서는 다음과 같습니다.

  | 열 | 뜻 |
  |---|---|
  | 채널 | CH1~CH5 |
  | 회전수 (rpm) | 장비의 회전 속도 |
  | 볼 개수 | 베어링 볼 개수 (1은 베어링 미사용) |
  | 최대 피크 RMS (mm/s) | FFT에서 가장 큰 피크의 진동 크기 |
  | 기준 (≤4.5) | 만족 / 불만족 / 재계측 |
  | 1X RMS, 2X RMS, BPFO RMS | 각 주파수 성분의 크기 (베어링 미사용 채널의 BPFO는 `-`) |
  | 결함 진단 | 최종 판정 |

- **`result-N.png`**: 위쪽에 채널별 FFT 그래프, 아래쪽에 판정 설명 텍스트가 들어 있습니다. 그래프의 세로줄은 1X, 2X, 베어링 주파수이고, 가로 점선은 허용 기준(4.5 mm/s)입니다. 에이전트 모드로 실행했다면 `[Claude 에이전트 진단]`도 함께 들어갑니다.

실행할 때마다 가장 큰 번호 + 1로 새로 만들기 때문에 **이전 결과를 덮어쓰지 않습니다.** (`result-1`, `result-2`, ...) 이 파일들은 `.gitignore` 대상이라 커밋되지 않습니다.

### 사람 검수 승인 (선택)

결과를 사람이 직접 확인했다는 기록을 남기려면 터미널에서 직접 실행합니다. (Claude Code 안에서는 `! python approve.py result-3`)

```
python approve.py result-3          # 채널별 판정을 직접 입력하고 yes로 승인 -> review-3.json 생성
python approve.py result-3 --check  # 승인 여부와, 승인 후 결과 파일이 바뀌지 않았는지 확인
```

`review-N.json`에는 검수자, 시각, 결과 파일 해시, 사람 판정과 에이전트 판정의 불일치가 기록됩니다. 에이전트는 이 파일을 만들거나 고칠 수 없습니다. 결과 파일처럼 `.gitignore` 대상입니다.

## 7. 용어와 판정 규칙

| 용어 | 설명 |
|---|---|
| FFT | 시간 신호를 주파수별 크기로 바꾸는 계산. 어떤 주파수에서 진동이 큰지 보여 줍니다. |
| RMS (mm/s) | 진동의 크기를 나타내는 대표값. 이 프로그램의 FFT 진폭 단위입니다. |
| 1X | 회전 주파수 = rpm / 60 (Hz). 예: 1800 rpm이면 30 Hz |
| 2X | 1X의 2배 주파수. 축 정렬 불량에서 커집니다. |
| BPFO | 베어링 외륜 결함 주파수 = 회전주파수 / 2 × 0.8 × 볼 개수 (약산식) |
| 최대 피크 RMS | FFT에서 가장 큰 피크의 RMS. 기준 비교에는 시간신호 전체 RMS가 아니라 이 값을 씁니다. |

장비(채널)마다 회전수가 달라서 1X와 BPFO는 **채널별 rpm과 볼 개수로 따로 계산**합니다.

판정은 아래 순서로 위에서부터 적용합니다.

0. 2 Hz 미만 저주파 노이즈가 20 mm/s 초과: **재계측 권장** (아래 규칙은 적용하지 않음)
1. 최대 피크 RMS가 기준(4.5 mm/s) 이하이고 베어링 성분/1X ≥ 0.7: **베어링 점검 요망**
2. 기준 이하이고 이상 징후 없음: **정상**
3. 기준 초과이고 2X/1X ≥ 0.5: **정렬 요망**
4. 기준 초과이고 2X/1X < 0.5 (1X 지배): **발란싱 요망**

볼 개수가 1인 채널은 베어링 판정을 하지 않고, FFT 그림에도 베어링 세로줄을 그리지 않습니다.

## 8. 테스트

```
uv run pytest
```

모든 테스트가 `passed`로 끝나면 정상입니다. 판정 경계값(기준 4.5, 2X/1X 0.5, 베어링/1X 0.7, 저주파 20)과 훅 동작도 검사합니다.

## 9. 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| `uv: command not found` 또는 `uv`를 찾을 수 없음 | uv 설치 후 터미널을 다시 열어야 합니다. 1장 참고 |
| `계측 데이터 없음` 또는 `...xlsx 없음` | `data/` 폴더의 파일이 없습니다. `uv run python vibe_agent.py --make-data`로 생성하세요. |
| API 오류, 인증 오류 | 키가 맞는지, 네트워크가 되는지 확인하세요. 급하면 `--offline`으로 실행합니다. |
| 키를 설정했는데 규칙 기반으로만 실행됨 | 키는 터미널 창마다 따로 설정해야 합니다. 같은 창에서 설정 후 실행했는지 확인하세요. |
| UI 창이 안 열림 (`tkinter` 오류) | Linux는 `sudo apt install python3-tk`. 다른 OS는 Python을 공식 설치본으로 다시 설치합니다. |
| 한글이 깨져 보임 | 프로그램은 출력을 UTF-8로 맞춥니다. 그래도 깨지면 터미널 글꼴/인코딩(UTF-8)을 확인하세요. |
| `result-N.xlsx`가 열린 상태에서 오류 | 엑셀에서 파일을 닫고 다시 실행하세요. 새 번호로 저장하므로 보통 문제없습니다. |
| fs(샘플링 주파수) 오류 | 입력 엑셀의 시간 간격이 5120 Hz가 아닙니다. 5장의 데이터 형식을 확인하세요. |

## 10. 폴더 구성과 문서

```
vibe-agent/
├─ vibe_agent.py      프로그램 전체 (신호 생성, FFT, 판정, 에이전트, UI, 결과 저장)
├─ approve.py         사람 검수 승인 파일(review-N.json) 생성/확인
```
